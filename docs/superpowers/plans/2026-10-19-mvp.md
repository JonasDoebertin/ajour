# SimpleLogin for macOS MVP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A menu-bar-only macOS app that enables SimpleLogin aliases for a limited time, notifies when mail arrives, reliably disables them again, and creates new aliases quickly.

**Architecture:** All logic that can be tested without UI lives in a local Swift package `SimpleLoginKit` (API client, state-aware toggling, persisted timer engine, mail-arrival detection, Keychain storage, menu model). A thin SwiftUI app target `SimpleLoginMac` (generated by XcodeGen) wires it to `MenuBarExtra`, windows, notifications, wake/quit handling, and launch-at-login.

**Tech Stack:** Swift 6 (strict concurrency), SwiftUI, Observation, Swift Testing, URLSession, Security (Keychain), UserNotifications, ServiceManagement. XcodeGen (dev tool, already installed at `/opt/homebrew/bin/xcodegen`) generates the Xcode project.

**Spec:** `docs/superpowers/specs/2026-10-19-mvp-design.md`

## Global Constraints

- Deployment target macOS 26.0; build with Xcode 27 / Swift 6.4, Swift language mode 6.
- No third-party runtime dependencies.
- App Sandbox on, entitlement `com.apple.security.network.client`; `LSUIElement = YES` (no Dock icon).
- API base URL `https://app.simplelogin.io`, auth header `Authentication: <api key>`; `401` = invalid key; error bodies `{"error": "..."}` may be shown as-is.
- API key lives only in the Keychain. Never log it or write it anywhere else.
- Never call `POST /api/aliases/:id/toggle` without first reading the alias's current `enabled` state.
- Durations are exactly 5 minutes, 1 hour, 24 hours.
- Activity polling every 15 seconds; clock-skew tolerance 5 seconds; quit/sign-out disable budget 5 seconds; persistent-failure notification after 120 seconds of failed disabling.
- All code, comments, UI copy, and commit messages in English. Commit messages describe intent, one line for small changes.
- Signing: ad-hoc ("Sign to Run Locally", `CODE_SIGN_IDENTITY = "-"`), because this Mac has no Apple Development identity yet. Switch to the team identity when available. Expect a Keychain access prompt after rebuilds; that's the ad-hoc signature changing, not a bug.
- Bundle identifier `de.doebertin.simplelogin-macos`, display name "SimpleLogin for macOS".

## Review Focus

1. **Mac wakes without network:** disabling an expired alias fails. The record must stay, retries must back off (5, 10, 20, 40, then every 60 s), and after 120 s one "Could not disable" notification appears. Covered in Task 5.
2. **Alias changed elsewhere during a timer** (disabled or re-enabled via the web app): no blind toggle. Expiry of an already-disabled alias just drops the record. Covered in Tasks 3 and 5.
3. **API key revoked while timers are pending:** no retry storm, one "API key invalid" event, and pending disables resume right after a new key is saved. Covered in Task 5.
4. **Timer file unreadable:** load must not silently return an empty list and later overwrite the file, because that loses track of enabled aliases. Covered in Task 4.
5. **Old or repeated activity:** mail forwarded before `enabledAt`, the same activity seen again, or a re-check after Extend must not notify twice. Covered in Task 6.

### Task 5: Timer engine: enable, extend, disable, expiry, retry

**Files:**
- Create: `Timers/TimerEngine.swift`
- Test: `TimerEngineTests.swift`

**Interfaces:**
- Consumes: `AliasSwitch`, `AliasAPI`, `TimerStore`, `TimerRecord`, `AliasDuration`, `APIError`.
- Produces:
  ```swift
  @MainActor @Observable public final class TimerEngine {
      public init(store: any TimerStore, now: @escaping @Sendable () -> Date = Date.init)
      public var api: (any AliasAPI)?                       // nil = signed out; operations throw TimerEngineError.notSignedIn
      public private(set) var records: [TimerRecord]
      public private(set) var failures: [Int: DisableFailure]
      public private(set) var loadError: TimerStoreError?   // set when store.load() failed; saving is then refused (Review Focus 4)
      public var hasActiveTimers: Bool { get }
      public func record(for aliasID: Int) -> TimerRecord?
      public func enable(aliasID: Int, for duration: AliasDuration) async throws -> TimerRecord
      public func startTimer(for alias: Alias, duration: AliasDuration) throws -> TimerRecord   // alias already enabled; no API call
      public func extend(aliasID: Int, by duration: AliasDuration) throws
      public func disableNow(aliasID: Int) async throws
      public func processDue() async -> [TimerEvent]
      public func nextDueDate() -> Date?
      public func resumeAfterKeyChange()                      // clears .unauthorized failures
      public func disableAll(within budget: Duration) async -> Bool   // true when no records remain
  }
  public enum DisableFailure: Equatable, Sendable {
      case transient(firstFailedAt: Date, attempts: Int, nextRetryAt: Date, reported: Bool)
      case unauthorized
  }
  public enum TimerEvent: Equatable, Sendable {
      case disabled(aliasID: Int, email: String)
      case disableKeepsFailing(aliasID: Int, email: String)
      case unauthorized
  }
  public enum TimerEngineError: Error, Equatable { case notSignedIn, storeUnavailable }
  ```
  Semantics:
  - `enable` on an alias that already has a record behaves like `extend`.
  - `enable` sets `enabledAt = now` and `expiresAt = now + duration`. `extend` changes only `expiresAt`, to now plus the duration.
  - `disableNow` removes the record and any failure entry for that alias.
  - `processDue` handles records where `expiresAt <= now`, skipping those with `.unauthorized` and those whose `nextRetryAt > now`. It calls `ensureDisabled`.
    - On success: remove the record and emit `.disabled`.
    - On `APIError.unauthorized`: mark every pending record `.unauthorized` and emit one `.unauthorized` per transition, not per record.
    - On any other error: set `.transient` with a backoff of `[5, 10, 20, 40, 60]` seconds, indexed by attempts and capped at 60. Once `now - firstFailedAt >= 120` and `reported == false`, emit `.disableKeepsFailing` and set `reported = true`.
  - `nextDueDate` is the minimum over non-unauthorized records of `nextRetryAt ?? expiresAt`.
  - Every mutation of `records` saves through the store.

**Interfaces:**

- Produces:
