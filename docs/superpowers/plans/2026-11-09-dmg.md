# DMG Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every release ships a signed, notarized and stapled `Ajour.dmg` that opens to the owner's designed window, and the website and README download it.

**Architecture:** `scripts/build-dmg.sh` turns an app bundle into a disk image with `dmgbuild` (pinned by hash, in a virtual environment) and the settings in `packaging/dmg/settings.py`. A composite action signs, notarizes, staples and checks the image; the release workflow runs it after the app's notarization and attaches and attests both files. The website switch is a separate pull request after the first release with a disk image.

**Tech Stack:** bash, Python 3 stdlib, dmgbuild 1.6.7 (with ds_store and mac_alias), hdiutil, tiffutil, codesign, notarytool, stapler, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-09-dmg-design.md`

## Global Constraints

- English for code, comments, docs and commit messages; generalized, atomic commit messages.
- File name `Ajour.dmg` on tag runs, `Ajour-run<number>.dmg` on manual runs. Volume name `Ajour`.
- Window content 640 × 400 pt, icon view, icon size 128, label text 13, no toolbar, sidebar, path bar, status bar or tab view.
- `Ajour.app` at (160, 190), `Applications` → `/Applications` at (480, 190), points from the top left.
- Background files: `packaging/dmg/background.png` (640 × 400) and `packaging/dmg/background@2x.png` (1280 × 800), copied unchanged from `/Users/jonas/.pencil/documents/ce6f3bd8-1bc0-49f2-af78-d4daae6064d5/dmg/`.
- Volume icon: the app's `Contents/Resources/AppIcon.icns` (implementer's call recorded in the spec's "Left to the builder").
- No Finder or AppleScript in the build. dmgbuild and its dependencies are installed with `pip install --require-hashes` from `packaging/dmg/requirements.txt`.
- `Ajour.zip`, its attestation, `pages.yml` and the update feed stay unchanged.
- Website and README links stay on the zip until the first release with `Ajour.dmg` is published (Task 4 waits for that).

## Review Focus

- Finder's window bounds may include the title bar, so a 640 × 400 window could clip the background or show scroll bars. Expected: the background fills the content area exactly. Pinned by Task 1 step 6 (manual look) and Task 5's manual checks.
- A tag rerun after the release was published. Expected: the job fails before touching either file. Pinned by Task 3 step 3's review of the attach step.
- A manual run. Expected: both `Ajour-run<n>.zip` and `Ajour-run<n>.dmg` are separate artifacts, because `upload-artifact` with `archive: false` takes one file. Pinned by Task 3 step 6.
- The zip's provenance after attesting two subjects. Expected: `gh attestation verify` on `Ajour.zip` still passes in `pages.yml`. Pinned by Task 5 step 3 (feed deploy succeeds).
- A disk image whose app lost its stapled ticket. Expected: `stapler validate` passes on the app inside the mounted image. Pinned by Task 3 step 6.

### Task 3: Sign, notarize and ship the disk image

**Files:**
- Create: `.github/actions/disk-image/action.yml`
- Modify: `.github/workflows/release.yml`, `docs/ci.md`, `docs/mvp-manual-checks.md`

**Interfaces:**
- Consumes: `scripts/build-dmg.sh` (Task 1), `submit-for-notarization` (Task 2).
- Produces: composite action `disk-image` with inputs `app` (stapled app), `name` (file name without extension), `team-id`, `api-key`, `api-key-id`, `api-issuer-id`; output `path` = `build/<name>.dmg`.

- [ ] **Step 1: Write the action.** Steps: build with `scripts/build-dmg.sh "$APP" "build/$NAME.dmg"`; `codesign --sign "Developer ID Application" --timestamp` the image; check with `codesign --display --verbose=2` that `TeamIdentifier=<team-id>` and a `Timestamp=` line are present, failing with an `::error::` like the app check; submit with `subject: the disk image`; `xcrun stapler staple` and `xcrun stapler validate` the image; `spctl --assess --type open --context context:primary-signature --verbose=4` must report `source=Notarized Developer ID`, else `::error::Gatekeeper does not accept the disk image as notarized.`
- [ ] **Step 2: Call it in `release.yml`** right after the `notarize` step, with `name` = `Ajour` on tag runs and `Ajour-run<run_number>` otherwise (same expression as `archive-name`). Give the step `id: disk-image`.
- [ ] **Step 3: Ship both files.** Attestation `subject-path` lists the zip and the image (one per line). The attach step passes both files to `gh release create` and to `gh release upload --clobber`; the published-release error reads "Release $TAG is already published, so its Ajour.zip and Ajour.dmg stay as they are. Release a new version instead." and still exits before uploading anything. Add a second `upload-artifact` step for the image with the same settings as the zip's.
- [ ] **Step 4: Document.** `docs/ci.md` release bullet and signing paragraph: the release also attaches `Ajour.dmg`, signed, notarized and stapled, built with dmgbuild from `packaging/dmg/`; manual runs keep `Ajour-run<number>.dmg` too; both files get provenance attestations on tag runs. `docs/mvp-manual-checks.md` gets a "## Disk image" section: opens to the designed window in Light and in Dark Mode with readable names; dragging installs Ajour; the installed app opens without a Gatekeeper warning; `spctl --assess --type open --context context:primary-signature -v Ajour.dmg` reports "Notarized Developer ID".
- [ ] **Step 5: Check and commit.** `actionlint` clean; commit "Sign, notarize and attach the disk image to releases".
- [ ] **Step 6: Run it (controller, needs the owner's go to push).** Push the branch, run `gh workflow run release.yml --ref dmg`, wait for success. Download both raw artifacts with `gh api .../actions/artifacts/<id>/zip` (not `gh run download`, which breaks symlinks). For the image: `spctl` as above reports "Notarized Developer ID"; mount it read-only and `xcrun stapler validate` the app inside; `codesign --verify --deep --strict` the app inside.
