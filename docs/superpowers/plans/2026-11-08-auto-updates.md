# Auto-updates Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ajour finds, downloads and installs new versions with Sparkle 2, restarts for automatic updates only at a quiet moment, and keeps running timers across the restart.

**Architecture:** A thin `UpdateController` wraps `SPUStandardUpdaterController` and turns Sparkle's delegate callbacks into an observable `UpdateMenuState`, a notification, and a pending install that a pure `UpdateRestartPolicy` releases. `AppModel.prepareForTermination` gets a mode that keeps timers for an update relaunch. The Pages workflow builds, signs and verifies a one-item appcast from GitHub's latest release with a stdlib Python script and OpenSSL.

**Tech Stack:** Swift 6, SwiftUI/AppKit, Swift Testing, Sparkle 2 (SwiftPM via XcodeGen), GitHub Actions, Python 3 stdlib, OpenSSL 3 (Ed25519).

**Spec:** `docs/superpowers/specs/2026-11-08-auto-updates-design.md`

## Global Constraints

- English everywhere: code, comments, docs, commits, UI copy. Inclusive language. Self-documenting code over comments.
- macOS 26.0 deployment target, Swift 6, App Sandbox stays on.
- Sparkle is the only third-party dependency. Pin an exact 2.x version.
- Feed URL: `https://ajour.email/appcast.xml`. Archive URL: `https://github.com/JonasDoebertin/ajour/releases/download/<tag>/Ajour.zip`.
- The release keeps a single asset, `Ajour.zip`.
- Fresh-timer window: 10 minutes. Re-check a pending install at least once a minute.
- Updates are off in Debug builds, demo mode and the unit-test host.
- Sparkle system profiling stays off.
- The EdDSA private key never appears in chat, logs, the repo or workflow output. Tests use throwaway keys.
- Commit messages describe intent, one line for small changes. Merges to `main` only via PR with green CI and the owner's approval.

## Prerequisite (owner, before Task 1)

The owner runs Sparkle's `generate_keys` (from the pinned Sparkle release's `bin/`), keeps a backup of the private key, exports it with `generate_keys -x <file>` (a base64 32-byte seed), stores it with `gh secret set SPARKLE_PRIVATE_KEY --env github-pages < <file>`, deletes the export, and gives the implementer the public key (base64, 32 bytes). Task 1 needs the public key.

## Review Focus

1. An update restart while an alias is being enabled: the timer must be saved and survive. Pinned by `updateRestartWaitsForEnablesInFlightAndKeepsTheirTimers` (Task 3) and `enableInFlightBlocksTheRestart` (Task 2).
2. A normal quit while an update is downloaded (install on quit, no relaunch) must still disable timed aliases. Pinned by `scheduledInstallDoesNotMarkARelaunch` (Task 2) and the manual check in Task 9.
3. The latest release predates Sparkle (no `SUPublicEDKey` in its app): the site must still deploy, without a feed. Pinned by `archiveWithoutPublicKeyIsSkipped` (Task 7).
4. Release notes with `&`, `<`, `]]>`: the feed stays valid XML. Pinned by `notesWithMarkupCharactersStayValidXML` (Task 7).
5. A timer whose `enabledAt` lies in the future (clock change): treat as fresh, don't restart. Pinned by `timerStartedInTheFutureIsFresh` (Task 2).

### Task 7: Appcast builder

**Files:**
- Create: `scripts/appcast.py`, `scripts/appcast_test.py`

**Interfaces:**
- Produces: CLI `python3 -I scripts/appcast.py --release <release.json> --notes <notes.html> --archive <Ajour.zip> --key-file <seed file> --output <appcast.xml>`. - [ ] **Step 2: Run** `python3 -I scripts/appcast_test.py`. Expected: FAIL (module missing).
- [ ] **Step 3: Implement.** Stdlib only. Ed25519 through `openssl` subprocesses with temporary files in a private temp dir (mode 0600):

  - public key PEM = DER prefix `302a300506032b6570032100` + 32-byte key;
